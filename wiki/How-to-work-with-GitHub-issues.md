# How to work with GitHub issues

Use GitHub issues to track experiment work in a way that makes progress visible and reviewable.

## Suggested structure

- One issue per experiment wave or per experiment cluster.
- Use checklists for the “Check & Refine” loop.
- Link commits/PRs to the issue.

## Labels (example)

- `phase-2`, `docs`, `perf`, `bug`, `refactor`, `validated`

## Definition of done

- The issue is done when the experiment(s) pass the output rubric and the docs build is clean.
